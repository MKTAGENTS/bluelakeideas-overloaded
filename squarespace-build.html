2

Paste preconnect + override CSS

This is the work that gives the page its Blue Lake look — and protects it from Squarespace's defaults trying to win the specificity battle.

  1. On the page, click Settings (gear icon)
  2. Open the Advanced tab
  3. In Page Header Code Injection, paste in this exact order:
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<style>
  /* …paste the full contents of overloaded-overrides.css here… */
</style>
⬇ Download overloaded-overrides.css (v2.0)
Why preconnect matters: without it, Libre Baskerville and DM Sans take an extra ~200ms to resolve on first paint. Preconnect tells the browser to open the Google Fonts connection immediately. Don't skip these two lines.
About !important: every rule in the override CSS uses !important. This is intentional — Squarespace's Site Styles inject inline styles with high specificity. Without !important, half the overrides would be ignored. This is the one CSS sin you commit on purpose.

4

Eyebrow class via Markdown block

Squarespace's Text block won't let you apply CSS classes. For every small-caps "eyebrow" label, use a Markdown block:

<p class="eyebrow">A New Book by Matt Elliott</p>

The override CSS targets .eyebrow and styles it as uppercase Deep Blue Lake DM Sans with 0.22em tracking. Without this, the eyebrow renders as plain body text.

Newsletter Block — bulletproof setup

This is the only revenue-relevant element on the page. Triple-check everything below.

5a. Block configuration

  1. Add a Newsletter Block inside Section ⑦
  2. Form fields: First Name + Email (both required)
  3. Button text: Join the Waitlist
  4. Success message: "You're on the list. Check your inbox — the first email's on its way."
  5. Disclaimer text (below form): No spam. Unsubscribe anytime.

5b. Storage → Mailchimp/Email (do not enable these)

Do not connect Squarespace Email or Mailchimp. HubSpot owns every send in this architecture. Squarespace's only job is form capture. If you connect Squarespace Email, you'll send duplicate welcome emails.

5c. Storage → Zapier (the only connection)

  1. Newsletter Block → Storage → click Connect next to Zapier
  2. You'll be redirected to authorize. Use a Squarespace API key with scope: Forms
  3. API key location: Squarespace Settings → Advanced → Squarespace API Keys → generate new → copy the key
  4. Paste into Zapier when prompted

5d. The Zap (one zap, three actions)

  1. Trigger: Squarespace → New Form Submission → select the /overloaded Newsletter Block
  2. Action 1: HubSpot → Create or Update Contact
    • Map First Name, Email
    • Set Lead Source = "Overloaded Waitlist"
    • Set Waitlist Joined Date = today (use Zapier's {zap_meta_human_now})
  3. Action 2: HubSpot → Add Contact to Static List → "Overloaded Waitlist"
  4. That's it. The list-add triggers the HubSpot welcome workflow automatically. Don't add a second zap to send the welcome email — HubSpot does it.
Test the full chain before going live. See Step 7 — every signup should land in HubSpot within 60 seconds AND trigger a welcome email arrival within 90 seconds.
6

Personal plan workaround (no Page Header Code Injection)

If the site is on Personal plan and upgrading isn't on the table yet:

  1. Add a Markdown block at the very top of /overloaded (above all other blocks):
<script>document.body.classList.add('overloaded-page');</script>
  1. Go to Design → Custom CSS (site-wide)
  2. Paste the override CSS, but prefix every selector with body.overloaded-page
body.overloaded-page h1 { font-family: 'Libre Baskerville', serif !important; }
body.overloaded-page .sqs-block-button-element { background: #005B54 !important; }
body.overloaded-page .sqs-block-newsletter input { font-size: 16px !important; }
Tradeoffs of this workaround:
  • Slower first paint — script runs after DOM ready, so there may be a flash of un-overridden content (FOUC)
  • Site-wide CSS file is now bigger — affects every page's parse time slightly
  • If the Markdown block fails to load, the whole page falls back to default Squarespace styling
Recommended: upgrade to Business plan. It's $11/mo more and gives you proper page-level code injection.

Common failures & their fixes

SymptomCauseFix
Fonts still showing as Squarespace defaults Google Fonts didn't load, or selectors lost specificity Verify preconnect lines are above <style>. Hard refresh (Cmd+Shift+R). Test in incognito.
Buttons still gray/default Squarespace inline styles winning The override CSS uses !important — confirm CSS is in Page Header Code Injection, not site-wide Custom CSS.
iPhone zooms in when tapping form input Input font-size below 16px Override CSS already enforces 16px on inputs. If still happening, check for conflicting Site Style.
Newsletter submit returns "error" Storage not configured Newsletter Block → Storage → confirm Zapier is connected and the Zap is "On" in Zapier dashboard.
Contact appears in Squarespace but not HubSpot Zap failed silently Zapier dashboard → Task History → look for failed run. Most common: missing First Name field mapping.
Welcome email never arrives HubSpot workflow not active OR list-add didn't fire HubSpot → Workflows → Overloaded Welcome → verify "Active" status. Check workflow history for the test contact.
Welcome email lands in spam Domain auth incomplete HubSpot Settings → Domains & URLs → check SPF/DKIM/DMARC all green. If not, add missing DNS records.
Page looks right in edit mode, broken when published Squarespace cache Hard refresh in incognito. Wait 2–3 min. Try mobile data instead of WiFi (different cache).
Override CSS leaked to other pages Pasted into Design → Custom CSS instead of Page Header Code Injection Move it. Page Settings → Advanced → Page Header Code Injection is the right place.
10

Cache busting & deployment

Squarespace caches CSS aggressively. After any change to Page Header Code Injection:

  1. Hard refresh in the browser: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows)
  2. Test in incognito/private window — bypasses your local cache entirely
  3. Different network — Squarespace's CDN can take 2-3 minutes to propagate. Switching to mobile data avoids stale CDN responses
  4. Versioned query string — if pulling external CSS, append ?v=2 (increment) to force re-download
Pre-launch deployment order:
  1. Build everything with page set to "Not Linked"
  2. Run the full Step 7 verification
  3. Run the full Step 8 mobile QA
  4. Schedule HubSpot launch sequence emails (don't enable them yet — schedule for future dates)
  5. Test signup with a final fresh email — confirm welcome arrives
  6. Only then: move page from "Not Linked" to the live nav, or share the direct URL

Compliance & spam prevention

GDPR / CCPA

  • The disclaimer "No spam. Unsubscribe anytime." sits below the form field — explicit consent context
  • Every HubSpot marketing email auto-includes an unsubscribe link in the footer (enabled by default)
  • HubSpot tracks unsubscribe status on each contact — those leave the list automatically
  • If you're collecting from EU residents: enable double opt-in in HubSpot's email settings (Settings → Marketing → Email → Subscriptions)

Spam filtering protection

  • Verified sending domain (covered in prerequisites) — non-negotiable
  • Avoid spam triggers in welcome subject line: no ALL CAPS, no excessive punctuation (!!!), no $$$, no "FREE"
  • Keep image-to-text ratio under 40% in every email
  • Include physical mailing address in email footer (CAN-SPAM requirement) — HubSpot adds this automatically if you fill in Settings → Marketing → Email → Subscription Types

Bot/spam form submissions

  • Squarespace's Newsletter Block has built-in reCAPTCHA — enable it in the block settings if seeing spam signups
  • Set up a Zapier filter: skip the zap if email field contains common spam patterns (test@test.com, etc.)
  • Monitor HubSpot's contact creation rate — sudden 50+ signups in an hour usually means a bot found the form
